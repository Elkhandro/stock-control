# ПР10 — тезисы к защите

## Предметная область

Вместо комнат и бронирований используются товары и складские операции. Это соответствует реальному проекту и не вводит фиктивные сущности.

## Менеджер операций

`OperationQuerySet` содержит:
- `active()` — активные операции;
- `cancelled()` — отменённые;
- `completed()` — завершённые;
- `for_date(day)` — операции за дату.

Условия вынесены из views в один переиспользуемый слой ORM.

## Миграция статусов

Ранее в БД был BooleanField `is_cancelled`. Миграция сначала добавляет CharField `status`, переносит True в CANCELLED и False в ACTIVE, затем удаляет старое поле. COMPLETED доступен для новых и изменяемых записей. В модели остаётся только поле status.

## Django Admin

ProductAdmin показывает активные операции через Count + filter, содержит OperationInline, редактирование остатка, поиск и фильтры. OperationAdmin содержит autocomplete_fields, list_select_related, фильтры, сортировку и массовые actions.

Группа Warehouse Operators создаётся миграцией с ограниченными правами без delete permissions. Для демонстрации создать отдельного staff-пользователя и добавить его в эту группу.

## Debug Toolbar

Панель подключается только при `DJANGO_DEBUG=1`. В панели SQL можно показать число запросов, COUNT для пагинации и запросы на странице операций/деталей. Для production DEBUG остаётся выключенным.

## Slug и GeneratedField

Unidecode транслитерирует кириллицу до slugify. Существующие товары обновляются миграцией. `get_absolute_url()` строит канонический slug URL; старый числовой URL сохранён. GeneratedField вычисляет `price * stock` на стороне БД.

## Демонстрация

1. Django Admin: товары, inline, активные операции, изменение остатка.
2. Django Admin: операции, фильтры, сортировка статуса, actions.
3. Список операций: менеджер, фильтрация и пагинация.
4. SQL-панель DDT: список, карточка операции, админка.
5. Показать миграцию статусов, QuerySet и тесты.
